# Mission Control (2026-07-22)

`memsub mission serve [--port 8769]` starts a single-page, phone-first ops
room: one dark page that answers, at a glance, what happened, what is
running, what is waiting on you, what did it cost. Stdlib-only HTTP
server (`memsub/mission.py`), same visual family as `vault_serve.py`'s
dashboard but bolder, and auto-refreshing via a plain `<meta refresh
content="120">` -- no client-side JS, nothing to keep alive.

```
.venv/bin/memsub mission serve --port 8769
# open http://127.0.0.1:8769/ on your phone or laptop
```

Every section is independently fail-soft: a broken data source renders
"unavailable" inside that section only, and the whole page assembly has
its own outer try/except as a last line of defense, so the page itself
can never return a 500.

## Sections, top to bottom

1. **WAITING ON YOU** -- entries from `~/.memsub/waiting-on-you.json` (see
   format below). If the file is absent, the section is hidden entirely
   (no header). If it exists but is malformed, the section shows with an
   "unavailable" body. memsub never writes to this file itself; only you
   (or another tool) creates/edits it. An example lives at
   `docs/examples/waiting-on-you.example.json`.

2. **TODAY'S SPEND** -- runs `npx ccusage@latest daily --json` in a
   background thread, at most once per 30 minutes, and caches the result
   to `<cache-dir>/spend.json` (`<cache-dir>` defaults to
   `~/.memsub/mission-cache`, overridable via `MEMSUB_MISSION_CACHE_DIR`
   for tests). Renders total cost + top model from the cache; a
   missing/stale (older than 1 hour) cache renders "spend: refreshing".
   Page render never blocks on the ccusage call.

3. **AGENTS NOW** -- for each directory in `~/.claude/projects` and
   `~/.claude-remote/projects` (deduplicated by `(device, inode)` so a
   symlinked/bind-mounted pair isn't double counted), session files
   (`*.jsonl`) modified in the last 24h: project name (the session file's
   parent directory name), minutes since last write, and a `LIVE` badge
   under 5 minutes. Shows a total count plus the 8 most recently active
   rows.

4. **OPEN LOOPS** -- reuses `memsub.loops.scan_loops` if importable (the
   import is guarded, so this module still works if `loops.py` is ever
   absent). Shows the interrupt-tier finding count and the top 3 reason
   labels. Links to `http://127.0.0.1:8766/loops`.

5. **BLACKBOX** -- last sweep time and incident count, read-only (`mode=ro`
   SQLite URI: never creates or writes the db file) from the
   `blackbox_sweeps` table in the default store
   (`$MEMSUB_DB` or `~/.memsub/memory.db`). Links to
   `http://127.0.0.1:8766/blackbox`.

6. **REPOS** -- for each git repo directly under `~/projects` (top-level
   only, max 8, sorted by most recent commit): branch, dirty-file count,
   age of the last commit. Each `git` call runs via `subprocess` with a 2s
   timeout; a single uncooperative repo renders "unavailable" fields for
   that row only and never breaks the rest of the section.

7. **LINKS ROW** -- static links to the other memsub servers: dashboard
   (`8766`), garden preview (`8767`), bridges (`8768`), product site
   (`8765`).

## `waiting-on-you.json` format

A JSON list of objects. Each entry needs at least `title`; `detail`,
`since`, and `link` are optional.

```json
[
  {
    "title": "Short summary of what's waiting",
    "detail": "One or two sentences of context.",
    "since": "2026-07-22T09:15:00",
    "link": "https://example.com/optional-link"
  }
]
```

- `title` (required, string) -- shown as the row's headline (links to
  `link` if present).
- `detail` (optional, string) -- one line of extra context.
- `since` (optional, string) -- any string is accepted and displayed
  as-is (an ISO timestamp is the convention, not enforced).
- `link` (optional, string) -- if present, `title` becomes a link.

File absent -> the WAITING ON YOU section is hidden entirely. File
present but not a JSON list, or an entry missing `title` -> the section
renders "unavailable" (fail-soft, never a 500). Empty list (`[]`) ->
section shows with "nothing waiting".

memsub never writes this file itself -- you (or another tool of yours)
own it, at `~/.memsub/waiting-on-you.json`.

## Assumptions made while building this

- "Project name" in AGENTS NOW is the session `.jsonl` file's immediate
  parent directory name (Claude Code's own per-project session layout),
  not a friendlier resolved project title.
- BLACKBOX's "incident count" is the `incidents` column of the most
  recent `blackbox_sweeps` row (the last sweep's count), not a running
  total across all sweeps ever recorded.
- The LINKS ROW ports (8766/8767/8768/8765) are static, documented
  conventions from the existing memsub servers (see
  `docs/vault-serve-2026-07-18.md`, `docs/demo-runbook-2026-07-22.md`);
  Mission Control does not verify those servers are actually running.
- `TODAY'S SPEND`'s "today" is matched by local calendar date against
  ccusage's `daily[].period` field, falling back to the most recent
  entry present if today's isn't in the output yet (e.g. right after
  local midnight, before ccusage has synced that day).
