# Public website: build-week submission (2026-07-21)

Ordered directly: "a professional level website which not only tells,
gives full technical details but most importantly demonstrates the
product." The public face of memsub for a build-week submission. Full plan
(Karpathy rule 1, assumptions, success criteria) recorded before any code
in `WORKLOG.md`'s 2026-07-21 entry. This doc is the short companion:
what shipped, where every claim traces to, and how to view it.

## What shipped

`site/index.html` + `site/assets/{style.css,script.js,img/}` -- a static,
zero-build-step page. Opens directly via `file://` and serves from any
static server (`python3 -m http.server` from `site/`). No framework, no
bundler, no external font or script load, matching the project's own
"dependencies: numpy" ethos.

Six sections, in order: hero (3-line pitch, exact wording per the brief
with one factual correction, see below), an interactive demo tour (5
steps: dashboard, graph, a readable note, ask-with-citations, the ripple
moment) plus an animated terminal replay of the real runbook and a "run it
yourself" block with the exact commands, how-it-works (a drawn inline SVG
pipeline diagram + 6 expandable technical stages), trust (provenance
diagram, the poisoning attack table, the honest L2/L3 gaps, sovereignty
rules), benchmarks (the 63.75% vs mem0 headline, per-category styled
bars, and a separate honest panel for the fully-local-8B numbers), and a
footer (local-first manifesto, licensing TBD note, built-by line, no
OpenClaw mention).

Visual design: near-black base (`#0a0b0d`), one teal accent (`#6fd6ff`),
tokens read directly from the shipped product's own `memsub/vault_serve.py`
`_CSS` block so the site and the product look like one system. An 8px
spacing grid, a system-ui/-apple-system body font (Inter-class without an
external font load) with monospace reserved for stat labels/terminal/code,
radial glow accents behind the hero and section heads, card surfaces at
`#14161a` with 1px 8%-white borders and 12px radius, scroll-triggered
fade-up reveals (`IntersectionObserver`, staggered, `prefers-reduced-motion`
respected throughout), and the benchmark table rendered as styled bars
instead of a raw table.

## Two corrections to the brief's own paraphrase

Claim discipline is stated as absolute for this task, so it overrides an
inexact instruction rather than the other way around. Full reasoning in
`WORKLOG.md`'s 2026-07-21 entry, assumption 7; summarized here:

1. The brief's hero copy and doc annotation attribute the 63.75%-beats-mem0
   figure to a "laptop 8B" answerer. Checked against
   `docs/locomo-v3-2026-07-18.md` directly: that run used **Sonnet as the
   answerer via the `claude` CLI subscription**, not qwen3:8b -- the whole
   point of the frontier-answerer experiments (`docs/locomo-jscore-2026-07-17.md`
   onward) was to put memsub on the same frontier-answerer footing mem0's
   own reproduced number already uses. The site's hero sentence drops the
   "on a laptop 8B" clause; the benchmarks section states plainly which
   answerer produced which number, and shows the genuine local-8B numbers
   (README) in a clearly separate panel, never merged with the Sonnet
   figure.
2. The brief's "single-hop 85 vs their 67.1" splices the single-hop number
   from a different, lower-overall config (v2, 52.5% overall) onto the
   63.75%-overall winning config's row. The site uses the matched-row
   number instead: single-hop 80.0% vs mem0's 67.1% (+12.9pp), straight
   from `docs/locomo-v3-2026-07-18.md`'s own "per category" table.

## Out of scope, stated plainly

No live `/ask` model call is made anywhere on the site (the task's own "no
LLM calls" rule) -- the ask-with-citations step replays memsub's real,
already-measured retrieval results from `docs/demo-2026-07-20.md`,
including the honest miss on "what does Maya charge". The ripple step
renders real report data as styled HTML, not a live UI (ripple has no UI
wiring yet, per `docs/ripple-2026-07-20.md`).
