# Build-week demo vault: Arjun Mehta

A fully synthetic, public-safe persona brain for demoing memsub: "Arjun
Mehta, AI engineer building Coldstart (an AI cold-outreach copilot) while
consulting on LLM integrations." The persona is modelled on Rustom's real
workflow (self-hosted vs API tension, evals, consulting, build-in-public),
but zero real-person data and zero data from Rustom's real vault appear;
every person, company, number, and event is invented. (Replaced the earlier
Maya Chen indie-game-dev persona on 2026-07-21.) Built entirely through
memsub's real public write paths (episode + provenance channel + store
append, graph backfill, consolidate, distillation) and committed so the demo
just works from a clean clone -- the real vault (`~/memsub-vault` +
`~/.memsub/memory.db`) is private and is never used here.

Generator: `scripts/build_demo_vault.py` (+ data in
`scripts/_demo_persona_data.py`), local qwen3:8b only, fully idempotent and
regenerable. See WORKLOG.md 2026-07-20 "Build-week demo vault" for the full
assumption list and the iteration history (three rebuilds were needed to get
the ripple showcase and decay right -- documented there, not glossed over
here).

## Regenerate from scratch

```bash
cd memory-sublayer
python3 scripts/build_demo_vault.py --fresh
```

Takes about 9-10 minutes on a shared local ollama daemon (qwen3:8b,
`think=False`): ~121 content-generation calls, graph backfill, one
consolidate pass (dedup + contradiction + fusion + decay), and 8 topic-note
generation calls. Safe to interrupt and re-run without `--fresh` -- every
episode id is a deterministic hash of its data tag, so a re-run only fills
in whatever is missing.

## Run the demo

```bash
cd memory-sublayer
python3 -m memsub.cli vault serve --vault demo/vault --db demo/memory.db --port 8768
```

Then open `http://127.0.0.1:8768/` -- dashboard, `/graph`, note pages, and
the 8 topic notes under "topics" all render directly from the committed
`demo/vault/` + `demo/memory.db`.

## The ripple showcase: inference stack (self-hosted -> Claude API)

The hero feature. `memsub.ripple.ripple()` on the memory "Arjun chose to
run Coldstart's inference on a self-hosted Qwen3 8B model, served by vLLM
on a rented RTX 4090 server..." (`kind="milestone"`, id
`fd2ddec55488318c8afe12466888dd5c7f6a6403`):

```bash
python3 -c "
from memsub.ripple import ripple, render_report
from memsub.store import EpisodicStore
import hashlib
def eid(tag): return hashlib.sha1(f'arjun-mehta-demo|{tag}'.encode()).hexdigest()
s = EpisodicStore('demo/memory.db')
r = ripple(s, eid('stack.decision.selfhost'), max_hops=2, vault_path='demo/vault')
print(render_report(r))
s.close()
"
```

Result (2026-07-21 Arjun rebuild): **18 affected items, total impact
29.0, all three tiers lit up**:

- **Derived directly (4)**: superseded by the later "switch to the Claude
  API" decision (reason `stack_switch`, a deliberate reversal applied via
  `store.log_event`); cited as a source in a real fusion episode over the
  self-hosting cluster (consolidate's LLM-judged fusion pass genuinely
  grouped the vLLM/RTX-4090 memories and judged them worth fusing); listed
  as a source in 2 topic notes (`inference-stack-and-tooling` and
  `key-project-decisions`).
- **Derived transitively (4)**: the Claude-API switch decision is itself a
  fusion source for 4 further fusion episodes (a real second-order fusion
  wave over the same entity cluster).
- **Associatively related (10)**: the vLLM quickstart, the GPU

### Why 3 rebuilds were needed (honest iteration log)

1. **First build**: the deliberate supersede chains were applied *before*
   graph backfill and consolidate. Since both only ever look at
   `store.active()` at call time, the engine decision was already inactive
   by the time fusion and entity-linking ran -- it could never be a fusion
   source or get associative-tier entities (associative tier came back
   empty). Fixed by reordering: graph backfill + consolidate run first,
   deliberate supersedes applied last (idempotent-guarded, so if
   consolidate's own contradiction judge already caught a pair, the manual
   step just skips).
2. **Second build**: with the fix above, consolidate's contradiction phase
   (which pairs same-`kind` episodes) happened to pair the Godot decision
   with an unrelated same-kind episode and auto-superseded it via
   `reason="contradiction"` before fusion ran in the same call -- stealing
   the engineered reversal and, again, excluding it from fusion. Fixed by
   giving that one episode a unique `kind="milestone"` no other record
   shares, making it mathematically unpairable in the contradiction phase.
3. **Third build**: `importance=15.0` (chosen to survive consolidate's
   decay phase) was too close to the threshold -- measured value for the
   earliest (January) episodes was 0.159-0.196, just under the 0.2 cutoff,
   and several early memories (including the pricing-research episode) got
   decayed as "forgotten" on the very first real pass, since decay's clock
   is wall-clock `time.time()` (today), not the persona's story time.
   Fixed by raising `importance` to 100.0, a 5x margin at the oldest date.

## Quarantine exhibit (the security story, made visible)

One episode ("Arjun bookmarked the launch page of a competing AI outreach
agent...") was written through the `imported`
channel (`memsub.provenance.CHANNEL_IMPORTED` -- no pipeline signal that
the content was actually observed), then tampered: one character flipped
directly in the `content` column via a raw `sqlite3 UPDATE`, bypassing
`store.append` entirely -- the same way a real tamper would happen. This
happened *before* `consolidate()` ran, so the real phase-0 signature check
(`memsub.provenance.channel_status`) is what caught it and logged the
`quarantined` event, not a fabricated one.

Verify:

```bash
python3 -c "
from memsub.store import EpisodicStore
s = EpisodicStore('demo/memory.db')
q = [e for e in s.all(namespace='arjun-mehta') if s.status(e.id) == 'quarantined']
for e in q:
    print(e.id, s.status(e.id), e.content[:80])
s.close()
"
```

The vault-serve dashboard's PROVENANCE donut and QUARANTINED tile both show
it (1 quarantined, red), and its synced note carries `status: quarantined`
in frontmatter. Screenshot: `docs/screenshots/2026-07-20-demo/dashboard-1280x900.png`.

## Retrieval sanity: the 3 planned demo questions

```bash
python3 -c "
from memsub.sdk import MemoryClient
c = MemoryClient(db_path='demo/memory.db', namespace='arjun-mehta', embedder='auto')
for q in ['what inference stack is Arjun using and why', 'what does Arjun charge', "what has Arjun decided about Coldstart's interface"]:
    hits = c.search(q, k=4)
    print('Q:', q)
    for h in hits:
        print(f'   [{h.score:.4f}] {h.episode.content}')
c.close()
"
```

`embedder='auto'`: real `nomic-embed-text` embeddings via the local ollama
daemon (pulled for this build), meaningfully better dense-signal ranking
than the zero-dependency hashing default for short natural-language
questions.

- **"what inference stack is Arjun using and why"**: rank 1 is the switch
  decision itself ("Arjun decided to switch Coldstart's inference from the
  self-hosted Qwen3 stack to the Claude API after evals..."), followed by
  the Claude tool-use docs note and the devlog explaining the switch.
  Sensible, on-topic, rank 1.
- **"what has Arjun decided about Coldstart's interface"**: rank 1 is
  exactly the right memory -- "Arjun decided to switch Coldstart's
  interface to a web dashboard, keeping a thin CLI only for power
  users..." Sensible, on-topic, rank 1.
- **"what does Arjun charge"**: top hits are real client memories (the
  Corvid Analytics contract, the Brightpath Legal briefing, the Lena
  Petrova hire) but do not surface the specific `consulting.rate.v1/v2/v3`
  dollar figures in the top hits. **Honest finding, not papered over**:
  this small demo corpus plus memsub's default hybrid retrieval tuning
  (RRF-fused BM25 + dense + recency/session signals) does not reliably
  surface a specific number for a paraphrased question with no shared
  vocabulary ("charge" vs "rate"/"dollars"/"hour"). A direct query
  ("consulting rate") hits the $160 rate memory at rank 1 -- a
  phrasing-sensitivity finding about the demo's tiny corpus, not a broken
  retrieval pipeline (the flat per-rank scores are expected
  reciprocal-rank-fusion behavior, 1/(60+rank), not a bug).
