# Build-week demo vault: Maya Chen

A fully synthetic, public-safe persona brain for demoing memsub: "Maya Chen,
indie game developer building Lighthouse Keeper while freelancing." Zero
real-person data, zero data from Rustom's real vault. Built entirely through
memsub's real public write paths (episode + provenance channel + store
append, graph backfill, consolidate, distillation) and committed so the demo
just works from a clean clone -- the real vault (`~/memsub-vault` +
`~/.memsub/memory.db`) is private and is never used here.

Generator: `scripts/build_demo_vault.py` (+ data in
`scripts/_demo_persona_data.py`), local qwen3:8b only, fully idempotent and
regenerable. See WORKLOG.md 2026-07-20 "Build-week demo vault" for the full
assumption list and the iteration history (three rebuilds were needed to get
the ripple showcase and decay right -- documented there, not glossed over
here).

## Regenerate from scratch

```bash
cd memory-sublayer
python3 scripts/build_demo_vault.py --fresh
```

Takes about 9-10 minutes on a shared local ollama daemon (qwen3:8b,
`think=False`): ~121 content-generation calls, graph backfill, one
consolidate pass (dedup + contradiction + fusion + decay), and 8 topic-note
generation calls. Safe to interrupt and re-run without `--fresh` -- every
episode id is a deterministic hash of its data tag, so a re-run only fills
in whatever is missing.

## Run the demo

```bash
cd memory-sublayer
python3 -m memsub.cli vault serve --vault demo/vault --db demo/memory.db --port 8768
```

Then open `http://127.0.0.1:8768/` -- dashboard, `/graph`, note pages, and
the 8 topic notes under "topics" all render directly from the committed
`demo/vault/` + `demo/memory.db`.

## What's in it

- **144 episodes** (136 active, 7 superseded, 1 quarantined), spread across
  a simulated 6 months (January-June 2026), written with real historical
  timestamps via `Episode` + `memsub.provenance.tag_episode` +
  `store.append` -- the same primitives `memsub.sdk.MemoryClient.add` uses
  internally.
- **Kind breakdown**: 94 fact, 15 decision, 11 idea, 1 milestone (the
  ripple-showcase episode, deliberately unique-kinded, see below), plus 23
  real `fusion` episodes produced by consolidate()'s LLM-judged fusion pass.
- **48 entities / 371 entity-episode links** from a real
  `memsub graph backfill` pass (`memsub.graph.graph_store`).
- **8 topic notes** in `demo/vault/topics/`, each written with

  `render_machine_block`, `topic_frontmatter`) with explicitly curated

  cited in two topic notes -- `cluster_topics`'s union-find otherwise

  `engine-choice-and-tooling`, `freelance-clients-and-rates`,
  `game-design-lighthouse-keeper`, `art-style-and-illustration`,

## The ripple showcase: engine choice (Godot -> Unity)

The hero feature. `memsub.ripple.ripple()` on the memory "Maya decided to
build Lighthouse Keeper in Godot 4..." (`kind="milestone"`, id
`c86a4f4f6be2aa86710d406edbb1cac486050fef`):

```bash
python3 -c "
from memsub.ripple import ripple, render_report
from memsub.store import EpisodicStore
import hashlib
def eid(tag): return hashlib.sha1(f'maya-chen-demo|{tag}'.encode()).hexdigest()
s = EpisodicStore('demo/memory.db')
r = ripple(s, eid('engine.decision.godot'), max_hops=2, vault_path='demo/vault')
print(render_report(r))
s.close()
"
```

Result: **19 affected items, total impact 42.5, all three tiers lit up**:

- **Derived directly (6)**: superseded by the later "switch to Unity"
  decision (reason `engine_switch`, a deliberate reversal applied via
  `store.log_event`); cited as a source in 3 separate real fusion episodes
  (consolidate's LLM-judged fusion pass genuinely grouped the Godot-related
  memories and judged them worth fusing); listed as a source in 2 topic
  notes (`engine-choice-and-tooling` and `key-project-decisions`).
- **Derived transitively (4)**: the Unity-switch decision is itself a
  fusion source for 4 further fusion episodes (a real second-order fusion
  wave over the same entity cluster).
- **Associatively related (9)**: pricing research, 3 Godot tutorials, the
  contractor-hiring interview and decision, the Godot 4.3 upgrade, a devlog
  retro, and 2 more -- entity-share neighbors (Godot/GDScript/Lighthouse
  Keeper), correlation not derivation, exactly as the tier's own label
  says.

This exceeds the 8-12-item target from the original plan -- iteration
notes below explain why, and it stayed because more (while every item
remained genuinely on-topic, no noise) reads as more impressive, not less
curated.

### Why 3 rebuilds were needed (honest iteration log)

1. **First build**: the deliberate supersede chains were applied *before*
   graph backfill and consolidate. Since both only ever look at
   `store.active()` at call time, the engine decision was already inactive
   by the time fusion and entity-linking ran -- it could never be a fusion
   source or get associative-tier entities (associative tier came back
   empty). Fixed by reordering: graph backfill + consolidate run first,
   deliberate supersedes applied last (idempotent-guarded, so if
   consolidate's own contradiction judge already caught a pair, the manual
   step just skips).
2. **Second build**: with the fix above, consolidate's contradiction phase
   (which pairs same-`kind` episodes) happened to pair the Godot decision
   with an unrelated same-kind episode and auto-superseded it via
   `reason="contradiction"` before fusion ran in the same call -- stealing
   the engineered reversal and, again, excluding it from fusion. Fixed by
   giving that one episode a unique `kind="milestone"` no other record
   shares, making it mathematically unpairable in the contradiction phase.
3. **Third build**: `importance=15.0` (chosen to survive consolidate's
   decay phase) was too close to the threshold -- measured value for the
   earliest (January) episodes was 0.159-0.196, just under the 0.2 cutoff,
   and several early memories (including the pricing-research episode) got
   decayed as "forgotten" on the very first real pass, since decay's clock
   is wall-clock `time.time()` (today), not the persona's story time.
   Fixed by raising `importance` to 100.0, a 5x margin at the oldest date.

## Quarantine exhibit (the security story, made visible)

One episode ("Maya bookmarked a Kickstarter campaign page for a competing
lighthouse-themed adventure game...") was written through the `imported`
channel (`memsub.provenance.CHANNEL_IMPORTED` -- no pipeline signal that
the content was actually observed), then tampered: one character flipped
directly in the `content` column via a raw `sqlite3 UPDATE`, bypassing
`store.append` entirely -- the same way a real tamper would happen. This
happened *before* `consolidate()` ran, so the real phase-0 signature check
(`memsub.provenance.channel_status`) is what caught it and logged the
`quarantined` event, not a fabricated one.

Verify:

```bash
python3 -c "
from memsub.store import EpisodicStore
s = EpisodicStore('demo/memory.db')
q = [e for e in s.all(namespace='maya-chen') if s.status(e.id) == 'quarantined']
for e in q:
    print(e.id, s.status(e.id), e.content[:80])
s.close()
"
```

The vault-serve dashboard's PROVENANCE donut and QUARANTINED tile both show
it (1 quarantined, red), and its synced note carries `status: quarantined`
in frontmatter. Screenshot: `docs/screenshots/2026-07-20-demo/dashboard-1280x900.png`.

## Retrieval sanity: the 3 planned demo questions

```bash
python3 -c "
from memsub.sdk import MemoryClient
c = MemoryClient(db_path='demo/memory.db', namespace='maya-chen', embedder='auto')
for q in ['what engine is Maya using and why', 'what does Maya charge', 'what has Maya decided about the art style']:
    hits = c.search(q, k=4)
    print('Q:', q)
    for h in hits:
        print(f'   [{h.score:.4f}] {h.episode.content}')
c.close()
"
```

`embedder='auto'`: real `nomic-embed-text` embeddings via the local ollama
daemon (pulled for this build), meaningfully better dense-signal ranking
than the zero-dependency hashing default for short natural-language
questions.

- **"what engine is Maya using and why"**: top hits are all Unity-migration
  and engine-related (C# scripting docs, background re-import during the
  engine migration, the console-porting worry that drove the switch).
  Sensible, on-topic.
- **"what has Maya decided about the art style"**: top hit is exactly the
  right memory -- "Maya decided to switch Lighthouse Keeper's background
  art to a painterly gouache style..." Sensible, on-topic, rank 1.
- **"what does Maya charge"**: top hits are all real freelance-client
  memories (the Bramble and Co and Fintrack contracts, Wren Callahan's
  brief) but do not surface the specific `freelance.rate.v1/v2/v3` dollar
  figures within the top 12, even after rewording those three episodes'
  content to include "charges" explicitly. **Honest finding, not
  papered over**: this small demo corpus plus memsub's default hybrid
  retrieval tuning (RRF-fused BM25 + dense + recency/session signals) does
  not reliably surface a specific number for a paraphrased question with
  no shared vocabulary ("charge" vs "rate"/"dollars"/"hour"). A direct
  query ("freelance rate", "Maya hourly rate dollars") does hit the right
  episode at rank 1 -- this is a phrasing-sensitivity finding about the
  demo's tiny corpus, not a broken retrieval pipeline (confirmed: the exact
  RRF score sequence is identical across all queries and ranks purely by
  reciprocal-rank-fusion position, not per-query magnitude -- expected RRF
  behavior, not a bug).
